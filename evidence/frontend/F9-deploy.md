# F9 — Vercel deploy (needs human: no Vercel/Fly credentials in this environment)

This documents the exact project settings so a human can deploy `apps/web` in a few minutes; the
canonical runbook is [docs/09-deploy.md](../../docs/09-deploy.md) §B (owned by the human/setup, not the
frontend agent — this file is the frontend's checklist against it, not a replacement).

## Vercel project settings

```
vercel.com → Add New… → Project → Import jlee0229/hive-music
  Framework preset:   Next.js
  Root Directory:     apps/web        (tick "Include source files outside of the Root Directory in the Build Step")
  Build command:      next build      (default)
  Install command:    bun install     (Bun is detected from packageManager in the root package.json)
  Production branch:  main            (this branch, agent/frontend, gets a preview URL on every push)
Environment variables (all environments):
  NEXT_PUBLIC_API_URL      = https://<fly-app>.fly.dev
  NEXT_PUBLIC_WS_URL       = wss://<fly-app>.fly.dev/ws
  NEXT_PUBLIC_HIVE_ENGINE  = stub        ← flip to "real" once the engine's INT PR is on main (gate F8)
Deploy.
```

`apps/web/.env.local` (this repo, gitignored) already mirrors these for local dev against the mock:

```
NEXT_PUBLIC_API_URL=http://localhost:8080
NEXT_PUBLIC_WS_URL=ws://localhost:8080/ws
NEXT_PUBLIC_HIVE_ENGINE=stub
```

## What's already built and passing against the mock

- Manifest + icons: `apps/web/public/manifest.webmanifest` now lists real `icon-192.png`/`icon-512.png`
  files (generated by `apps/web/scripts/gen-icons.ts` — a placeholder mark; swap for real brand art
  whenever the team has it), plus an `apple-touch-icon.png` referenced from `app/layout.tsx`'s
  `metadata.icons`. No service worker, per the "stale bundle is worse than no offline" rule.
- Error states: `NO_ROOM` → "Hive not found" with a link back to `/`; `KICKED` → "Removed from hive".
  Both verified in `apps/web/e2e/f9-restart.spec.ts`.
- Restart recovery: `apps/web/mocks/scenarios/restart.json` (`chaos.restartAfterSec: 20`) drops every
  socket; the stub engine's own backoff-reconnect (unchanged, backend-owned) restores the same
  `clientId`. `ReconnectBanner` shows while `connection === 'reconnecting'` and clears once `WELCOME`
  comes back. Playwright confirms: banner appears within 25s of load, clears within 10s of appearing,
  and `localStorage`'s `hive:clientId:BZQ7` is identical before and after. Screenshot: `F9-restart.png`.

## Smoke test once deployed (human, ~5 minutes)

1. Open `https://<vercel-domain>/h/BZQ7` on the host phone → Lobby with the QR.
2. Scan with two phones → `/j/BZQ7` → tap to join → both reach "Synced ±N ms".
3. `/diag` on each phone: `connection` reads `open`, `rttMs` sane for Wi-Fi, `browserFamily` correct.
4. Kill/restart the Fly machine (or just wait for the mock's `restart.json` chaos locally) and confirm
   the banner clears within a few seconds without losing identity, role, or position.
5. If anything fails: check `fly logs` for the server, the Vercel deployment log for the web, and
   `https://<fly-app>.fly.dev/health` first (per docs/09-deploy.md §D, quick tunnels are a fallback
   if Fly/Vercel accounts aren't available in time).
